# Intervention-effectiveness ML

The preventive-action catalogue is not itself an intervention-effect model.
This module adds a separate observational causal-ML research pipeline.

## Estimand

For one hazard and one named intervention, estimate the conditional average
treatment effect (CATE) on a numeric damage-severity outcome:

- treatment = the named intervention was implemented in that site-time episode;
- control = the intervention was not implemented;
- outcome = comparable damage severity measured after the episode, with lower
  values representing less damage;
- covariates = conditions measured before the intervention decision.

A negative treatment effect means lower damage under the intervention. The UI
converts its sign to a positive "estimated damage reduction" for readability.
This is not a guaranteed benefit.

## Method

The research implementation uses site-grouped cross-fitting for nuisance
models (unweighted treatment-propensity logistic regression and treated/control
outcome forests), forms a doubly-robust pseudo-outcome, then fits an ExtraTrees
CATE model. On a later chronological holdout it evaluates both the average
doubly-robust effect and the learned context-specific policy (apply the action
only where predicted effect is beneficial); both must show a damage-reduction
signal with site-cluster bootstrap intervals before ranking eligibility.
This reduces within-site fold leakage and accounts for repeated episodes within
sites, but does not replace a separate geographic holdout or external validation. It checks minimum sample counts and treatment overlap. Ranking is
withheld unless the held-out mean effect is below zero, the entire 95% interval
is below zero, and overlap passes the configured gate.


## Comparative ranking safeguards

Even when separate action models pass their own evidence gates, the ranker
withholds cross-action ordering unless every eligible candidate has complete,
matching provenance for the same source study, owner, collection period,
outcome definition, treatment definition, geographic scope, hazard, outcome
unit, pre-treatment feature contract and chronological test cutoff. This prevents comparing
unlike damage measures or effects learned from unrelated populations as if
they were head-to-head evidence.

A permitted ordering is still based on context-specific point estimates. It
does not establish that the top-ranked action is statistically superior to
the next action. The current model does not yet calculate a valid
context-specific pairwise confidence interval for every action difference;
the output therefore remains a provisional research ordering, not a definitive
"best precaution" decision. Cost, feasibility, intervention quality,
engineering constraints and spillover effects are not automatically optimized.

## Data contract

One row per comparable observation episode (for example, household-season),
with `episode_id` unique within hazard/action and `site_id` identifying the
cluster used for grouped cross-fitting and uncertainty estimation. Required columns:

| Column | Meaning |
| --- | --- |
| episode_id | Unique household-season or asset-event observation identifier |
| episode_date | Episode/decision date used for chronological split |
| outcome_window_end | Last date used to measure the outcome; pre-test episodes crossing the split are purged |
| site_id | Stable site, asset, or treatment-assignment cluster identifier (e.g. panchayat) |
| hazard | Registered hazard label |
| action_id | Stable intervention identifier generated by the prevention catalogue |
| implemented | 1 if implemented, otherwise 0 |
| damage_outcome | Numeric post-episode damage severity; lower is better |
| other columns | Pre-intervention covariates only |

Do not include outcomes, repair costs, measurements after treatment, treatment
assignment fields, or variables caused by the intervention as features.
The training CLI additionally requires a provenance JSON sidecar with source
owner, source reference, collection period, outcome/treatment definitions,
geographic scope, known biases, access basis and an explicit
`pre_treatment_features` allowlist. The allowlist is reviewed before training;
structural, treatment and outcome columns are rejected even if nominated.
Synthetic data is rejected.

## Run

```bash
python scripts/train_intervention_effectiveness.py --data path/to/verified_episodes.csv --provenance path/to/provenance.json
```

No intervention dataset is currently registered as a validated, comparable
site-time episode table. The prevention catalogue emits stable action IDs; the
CSV must use the exact ID for the action definition being evaluated. Therefore the pipeline is implemented but cannot
honestly produce learned action-effect rankings yet. It must remain
`RANKING_WITHHELD` until suitable real observations are supplied and pass
the evidence gates.

## Assumptions and limits

Doubly-robust estimation does not remove unmeasured confounding. Consistency,
conditional exchangeability, positivity, no interference and comparable
outcome measurement are required. Disaster interventions often violate these
assumptions: authorities target the highest-risk locations, actions are bundled,
treatment quality varies, and infrastructure effects spill across locations.
The current model is preliminary research, not independently validated. It
must not issue evacuation orders, replace engineering assessment, or claim
lives/costs saved. Any public deployment requires domain-expert review,
independent geographic/temporal validation, sensitivity analysis for
unmeasured confounding, and prospective evaluation.
